# Evaluation notes

The skills grew from Python and repository-refactoring exercises, then writing tasks based on those exercises. This is a record of bounded development checks and agent appraisals. It does not establish performance across arbitrary repositories or human readers.

## Engineering

An earlier paired diagnostic covered two task families and two repetitions under each instruction package: eight executions. All passed the eleven registered case groups and their submitted suites detected the selected faults. The result was tied; it did not establish a refinement advantage.

A later contract check exposed a missed case. One package extraction's legacy API and command line used packaged settings after the operator changed live repository configuration. The original favorable appraisal was corrected after reproduction. The frozen reference shared the defect, showing a gap in the acceptance oracle; the original grades were left unchanged. The other three extraction submissions passed the supplemental live-policy comparison. These follow-up checks were not new main trials.

This failure is why the refactoring skill asks for consumer and configuration checks through the real execution path. Existing tests can share a defect with an implementation.

## Writing

Four initial author cases produced a technical paper and executive brief under each instruction package. The technical cases used full and compact workflows; the executive cases used direct and compact drafting. The same authors revised their documents after a real correction to the engineering evidence. Those revisions were follow-ups, not independent trials.

Initial review found a provenance error in the compact technical paper and clarity problems in both executive briefs. Some missing-link findings came from evaluator copies losing their package context and were withdrawn. After corrections, independent agent reviews and new agent readers found no material factual or comprehension defect. All three managed projects rejected stale records after a source change and passed final release checks; the direct brief used manual review.

The full technical project had 17 counted records initially and 19 after revision; compact had 7 at both stages. These counts exclude archives, outputs, caches, QA notes and the figure register. They do not measure time, cost or prose quality. Each writing helper suite passed 64 structural and compatibility checks. Synthetic fixture reviews are not comprehension evidence. That comparison delivered Markdown, so it did not evaluate PDF or Word rendering.

## Subsequent prose revision

The writing instructions later added located paragraph-level editing, meaning rechecks and representative before/after notes. The self-description PDFs in this repository exercise that revision separately from the frozen author trial. Their source fidelity was independently reviewed, fresh agent readers recovered the message and limits, and every rendered page was inspected.

One agent compared three passage pairs with condition labels concealed and presentation order varied. The result was mixed: it preferred the earlier technical evidence example and production explanation, and the revised executive opening. Shortening the technical passages had reduced inferential and operational specificity. Those details were restored and the final paper received a targeted evidence recheck and another fresh-reader check. The passage appraisal predates those restorations; it is not a verdict on the final PDFs.

## Limits and next use

There was one writing case per audience and condition, agent-only review and incomplete worker-inclusive usage accounting. Serving-model identities were not independently attested. No average quality, causal efficiency, cache savings or intended-human preference claim follows from these results.

The next useful evidence would come from repeated matched-source tasks with intended readers: preserve factual scope and qualifications as a gate, then check unaided recovery of the message separately from preference. Public use may also reveal installation or execution assumptions not exercised in these local checks.

Current example projects retain their manuscript, archived source records, built PDF and review evidence. Earlier comparison details appear in the self-reports' archived evaluation sources; private workspaces and experiment history are outside this distribution.
